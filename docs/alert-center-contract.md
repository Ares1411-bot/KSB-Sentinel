# 统一预警中心：原型接入约定

本版用于验证预警分类与处理流程，尚未发送真实通知。PLC 与预警中心通过同一标签页的会话快照共用事件及处理结果，附件仍为本地临时预览。

## 页面入口

- 顶部“预警中心”、铃铛，以及用户菜单中的“预警中心”。
- PLC 卡片“预警记录”和字段趋势统计入口保留 PLC 页面内专属弹窗／侧卡，不跳转平台中心；两边复用 PLC 事件模型与处理结果。详情与趋势放大保持原有 PLC 交互。
- `?view=alerts` 可直接打开中心。
- 项目 → 厂房 → 机组 → 设备四级范围选择。
- 业务页签：全部、待处理、处理中、已结束、无需处理、设备离线。
- 来源模块、来源类型、预警类型、等级、时间、关键字与排序独立筛选。
- 未结束统计不因列表时间过滤而隐藏较早的待处理事件。

## 共用事件结构

接入函数为 `window.SentinelAlertCenter.ingest(input)`。以下是结构示例，不代表实际模块数据：

```js
{
  id: 'APM:server-event-id', // 来源命名空间 + 来源事件 ID，全局唯一
  eventKey: 'APM:rule-id:device-id:metric-id',
  projectId: 'project-demo',
  plantId: 'plant-water',
  unitId: 'unit-water-main',
  pumpId: 'pump-omega-1',
  module: 'APM',
  sourceType: 'APM',
  type: 'efficiency',
  typeName: '能效偏离',
  title: '设备效率偏离设定范围',
  level: '一般',
  needManual: true,
  handler: null, // 可接收来源规则的处理人；本版中心不提供分配操作
  recordMode: 'merge', // merge / each
  notifyMode: 'first_upgrade', // first_upgrade / each
  start: Date.now(),
  dataState: 'abnormal',
  details: { 当前效率: '62%', 数据来源: '来源模块' }
}
```

后续新增模块会自动出现在来源筛选中；新增类型可通过 `typeName` 定义显示名称。`details` 是来源扩展区，没有专业数据时展示未提供，不补造结论。项目设备路径以平台设备目录为准。

详情概况统一为事件编号、预警来源、预警类别、所属设备、所属位置、首次预警时间和处理状态。来源携带处理人时增加配置处理人。消息正文放在独立“预警内容”中；没有正文或来源时间时显示未提供，不能以接收时间冒充预警时间。来源完整位置支持机房等额外层级，本次不修改四级筛选。

概况不再展示最高等级、数据状态、事件时长、实际处理人、通知或反馈计数。PLC 的等级和数据状态放在数据详情；实际处理人和时间放在处理结果；通知、反馈与更新信息放在事件过程。专业字段缺省时不补造结论。

`source-fields.js` 提供来源适配：PHM 为异常预警／故障诊断；APM 按最新确认分为能效／工况／性能风险，分别显示自己的风险建议，不能混入其他两类建议。来源类别优先，未提供类别时按来源类型映射；类别不明不兜底成性能风险。能效、工况建议文字为原型示例，性能建议沿用提供的截图。PHM 异常预警按端位、指标提供趋势／振动／频谱／相关性内容；故障诊断提供部件提示、来源百分比、时域／频域。未知来源保留扩展能力，不套用其他来源的专业展示。

事件过程使用 `shared/event-timeline.js` 展示适配。同一次变化的等级节点、数值节点，按共同 `changeId` 或反馈标识关联后显示为一条，例如“等级升级：提示→一般 / 0.29→0.31 MPa”。旧实时记录兼容同一毫秒附近的两次连续写入；已知十节点压力演示补齐演示关联标识。数值冲突、不同关联标识或无法确认关联的节点不合并。合并节点可展示起止时间，原始文本、时间及趋势数据不删除。PLC 专属卡片和预警中心使用同一展示规则；恢复、再次异常和处理结束仍为独立节点。

“数据详情”在右侧展开来源展示区域，按钮根据当前预警可提供的数据动态生成，不交叉展示其他模块的按钮。由 `data-views.js` 使用 HTML/SVG 绘制图表及设备图标，支持放大与工况／效率切换，不嵌入截图。参考值来自截图，波形和曲线为演示形状，不代表当前事件的测量数据。未提供的相关性／能效数据保留空状态。

## 状态与政策

| 维度 | 值及用途 |
| --- | --- |
| 人工处理状态 | pending → progress → closed；提交有效结果后结束 |
| 无需处理 | notice；不进入待处理数量，处理表单不可用 |
| 数据状态 | abnormal / recovered / unknown / offline / online / reminder |
| 配置处理人 | handler，来源配置的值原样保留 |
| 实际操作人 | processingActor / result.operator；本版使用 InternalDemo |
| 阅读状态 | read，只改变是否已读，不能结束事件 |

人工事件的数据恢复不会自动关闭事件。无需人工处理的预警可记录恢复时间；一次性提醒不要求恢复或人工处理。

归并和通知相互独立。`merge` 在同一设备、同一来源事件键、同一处理要求、同一记录政策下归并未结束事件；不会跨设备归并。`each` 每次来源预警建立独立记录。通知方式只是原型计数，没有实际推送。

## 处理与附件

- 支持直接提交处理结果，详情不提供“开始处理”按钮；仍可接收来源的处理中状态。
- 提交须包含处理方式和非空说明；照片、附件可选。
- 附件使用本地对象 URL 预览，生产接入需上传存储与权限接口。
- “建议”是详情左侧独立板块，替换原 AI 建议区域，直接展示来源的维修策略、风险提示或风险与建议；未提供时显示空状态。建议内容按用户截图重建为文字，风险分类可折叠，未接入真实分析。移除“来源分析与数据”栏目。
- PLC 来源事件处理后回传会话快照，返回 PLC 页面时更新处理结果及未处理数量。

## 演示验证

“整泵预警示例”单独验证 PHM 整泵算法反馈，不替换其他现有预警。列表一条事件，详情包含多个算法提示项及共享处理结果。联轴器三项名称及百分比取自截图，不能将其视为三个已确诊故障，也未定义百分比的算法含义。

详情中展开“演示算法反馈”，依次模拟重复反馈、新增振动提示、部分恢复、全部恢复。数据恢复不会自动结束人工事件。提交处理后可模拟再次异常，创建新的事件编号。正常模块不新增预警明细；缺失项不推断为恢复。按反馈 ID 去重并拒绝较早时间或其他泵的反馈。

`src/alerts/pump-demo.js` 为独立演示模型，字段名与明细 key 仅是建议结构。示例 JSON 在 `src/alerts/phm-pump-feedbacks.json`，构建到 `dist/alerts/data/phm-pump-feedbacks.json`，包含五次反馈及预期事件变化。通知次数与反馈次数独立，本示例只计首次通知，未提供等级时不构造等级升级。

中心底部“规则兼容演示”可以分别配置是否人工处理、事件归并方式、通知方式、来源是否带处理人；然后模拟预警、等级升级和恢复。政策变更只用于新的演示输入，不回写来源模块真实配置。

执行 `node tests/alerts-smoke.cjs` 可检查两个页面启动、筛选、阅读/处理分离、处理人保留、归并、逐次记录、跨设备隔离、新类型、PLC 回传、离线恢复、按来源的概况字段、数据详情四类示例及建议展开。该检查使用简化 DOM，不能替代真实浏览器视觉验收。
